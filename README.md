# gesture_AI

## 손이 보이는 무동작 상태 (`none`)

서버는 모델의 최상위 예측 라벨이 `none`이면 단어를 전송하지 않습니다.
`idle`, `no_gesture`도 같은 의미로 처리하며 앞뒤 공백과 대소문자는 무시합니다.
이때 이전 예측 투표도 초기화하므로 직전 수어가 계속 출력되지 않습니다.
신뢰도가 `CC_CONF_THRESHOLD`보다 낮은 예측도 출력하지 않고 투표를 초기화합니다.
`none`은 다른 수어의 후보 단어에도 포함되지 않습니다.

문장 생성 서비스에서도 LLM 호출 전에 `none`을 제거하므로 모델 재학습 전에도
`/cc/sentence`에 `"NONE 안녕하세요 NONE"`를 보내면 `안녕하세요`만 LLM에 전달합니다.
`NONE`만 보내면 LLM을 호출하지 않고 빈 `sentence`를 반환합니다.
대소문자와 앞뒤 공백은 무시하고 `idle`, `no_gesture`도 제거합니다.
후보 그룹의 첫 단어가 `none`이면 해당 그룹 전체를 건너뛰며 차순위 단어로 대체하지 않습니다.
LLM 미설정·호출 실패 시의 대체 응답에도 같은 필터를 적용합니다.

이미 인식한 단어가 있으면 `none`이 `CC_NONE_MIN_PREDICTIONS`회 연속 예측될 때
기존 단어들을 문장으로 마무리합니다. 기본값은 6회이며 예측 간격은
`CC_PRED_EVERY_N_FRAMES`를 따릅니다. 처음부터 무동작이면 단어나 문장을 생성하지 않습니다.
`/cc?debug=1`의 `prediction` 이벤트에서 `reason: "none_label"`을 확인할 수 있습니다.

### 모델 준비

이 저장소에는 촬영·학습 파이프라인과 모델 가중치가 포함되어 있지 않습니다.
기존 학습 환경에서 다음 작업이 필요합니다.

1. 기존 수어와 동일한 좌표 추출 방식으로 **손은 보이지만 수어를 하지 않는 영상**을 수집합니다.
   가만히 있는 손, 손 올리기·내리기, 머리 만지기, 동작 전후의 움직임 등을 포함합니다.
   의도한 수어를 수행하는 구간은 `none`으로 라벨링하지 않습니다.
2. 기존 데이터와 동일한 형식의 `none` 클래스로 추가합니다. 서버 기본 입력은
   `(30, 88)` 시퀀스이며 각 프레임은 왼손 21점, 오른손 21점, 어깨 2점의 `(x, y)`입니다.
   학습 전처리도 서버의 `_normalize_sequence`와 동일한 시간축별 평균·표준편차 정규화를 사용해야 합니다.
   촬영 영상을 먼저 학습용·검증용으로 나눈 뒤 시퀀스를 잘라 같은 영상이 양쪽에 섞이지 않게 합니다.
3. `none`을 포함한 전체 클래스 수로 출력층을 구성해 재학습합니다.
   `none`의 인덱스는 고정할 필요가 없습니다.
4. `model_state_dict`, **`none`을 포함한 `idx2label`**, `input_dim`을 체크포인트에 저장하고
   `weights/best_gru.pt`로 배치한 뒤 서버를 재시작합니다. 모델 파일은
   `best_bigru.pt`, `best_gru.pt`, `best_bigru30.pt` 순서로 찾으므로 이전 파일이 있으면
   우선순위에 주의하세요. 현재 서버의 체크포인트 로더는
   `GRUClassifier`를 생성하므로 이 구조와 호환되는 가중치를 사용해야 합니다.

기존 가중치에 라벨 이름만 추가하면 출력층 크기가 맞지 않으며 무동작도 학습되지 않습니다.
`none`이 없는 기존 모델은 계속 로드할 수 있지만 시작 로그에 재학습 필요 경고가 표시됩니다.
`util/config.py`의 `LABEL2IDX`와 `NUM_CLASSES`는 메타데이터가 없는 기존 모델용 기본값이므로
기존 가중치를 유지하는 동안 임의로 클래스만 추가하지 마세요.

검증: `python -m unittest discover -s tests -v`

gesture_AI는 수어 동작을 실시간으로 인식하고, 인식된 단어 후보를 자연스러운 한국어 문장으로 변환하는 AI 기반 수어 번역 서버입니다.

## 프로젝트 개요

본 프로젝트는 수어 사용자의 손동작을 키포인트 데이터로 변환한 뒤, 딥러닝 모델을 통해 수어 단어를 예측하고, 예측된 단어들을 자연스러운 한국어 문장으로 복원하는 것을 목표로 합니다.

서버는 FastAPI 기반으로 구현되었으며, WebSocket을 통해 실시간 키포인트 데이터를 수신합니다. 수신된 데이터는 PyTorch 기반 BiGRU 모델에 입력되어 수어 단어로 분류됩니다. 이후 인식된 단어 후보들은 Ollama 기반 로컬 LLM을 통해 자연스러운 한국어 문장으로 변환됩니다.

또한 Faster-Whisper 기반 STT 기능을 함께 제공하여 음성 스트림을 실시간 텍스트로 변환할 수 있습니다.

## 핵심 기능

### 1. 실시간 수어 인식

클라이언트에서 추출한 키포인트 데이터를 WebSocket으로 수신하고, 일정 프레임 단위로 수어 단어를 예측합니다.

입력 데이터는 손과 어깨의 좌표 정보를 포함한 88차원 키포인트 벡터이며, 30프레임 단위의 시퀀스로 구성되어 모델에 전달됩니다.

### 2. BiGRU 기반 수어 단어 분류

88차원 키포인트 시퀀스를 입력으로 받아 BiGRU 모델을 통해 수어 단어 클래스를 분류합니다.

양방향 GRU를 사용하여 손동작의 시간적 흐름을 학습하고, 마지막 time step의 출력을 기반으로 최종 단어 클래스를 예측합니다.

### 3. 입력 프레임 검증

수신한 키포인트 데이터가 정상적인지 검증합니다.

프레임 크기, NaN 또는 Infinity 여부, 손 랜드마크의 중복 정도, 어깨 좌표 간 거리 등을 확인하여 잘못된 입력 데이터를 필터링합니다.

### 4. 예측 안정화

모델의 softmax 결과에서 Top-K 후보 단어를 추출하고, confidence threshold를 기준으로 신뢰도가 낮은 예측을 제외합니다.

또한 최근 예측 결과를 기반으로 majority voting을 적용하여 순간적인 오분류를 줄이고 안정적인 단어 예측을 수행합니다.

### 5. 문장 종료 감지

사용자가 손을 내리거나 일정 시간 동안 유효한 수어 동작이 감지되지 않으면 문장이 끝난 것으로 판단합니다.

이를 통해 단어 단위 예측 결과를 문장 단위로 묶어 처리할 수 있습니다.

### 6. 로컬 LLM 기반 문장 복원

수어 인식 모델이 예측한 단어 후보들을 Ollama 기반 로컬 LLM에 전달하여 자연스러운 한국어 문장으로 변환합니다.

단어 후보를 단순히 나열하는 것이 아니라, 문맥상 가장 적절한 단어를 선택하고 필요한 조사와 어미를 보완하여 최종 문장을 생성합니다.

Ollama 모델이 설정되어 있지 않거나 호출에 실패한 경우에는 1순위 후보 단어를 연결하는 fallback 방식을 사용합니다.

### 7. 실시간 STT 기능

별도의 WebSocket 엔드포인트를 통해 음성 데이터를 수신하고, Faster-Whisper 모델을 사용하여 한국어 음성을 텍스트로 변환합니다.

오디오 스트림을 일정 간격으로 추론하여 변경된 텍스트를 클라이언트에 전달합니다.

### 8. 서버 상태 확인

루트 경로와 health check API를 통해 서버가 정상적으로 동작하는지 확인할 수 있습니다.
